# MCP 技能样板（Template）

这是一个**复制即用**的技能模板：把本文件整份复制到新目录，改掉占位符，就得到一个可被 AI 自动加载并驱动 MCP 工具的技能。

MCP 负责"**能调用什么**"（工具与参数），技能负责"**该按什么顺序调、结果怎么讲给用户**"（流程与表达）。两者配合才能稳定产出。

---

## 第一步：先拿到工具清单

技能是围绕**真实存在的工具**写的，不要凭想象编工具名。先让 AI 列出目标 MCP 服务器的工具：

> 列出 <server-name> 这个 MCP 服务器提供的所有工具，包括每个工具的参数与说明。

或者直接翻客户端的 MCP 配置 / 服务端源码里的工具注册部分。

把结果填进下面表格，**工具名必须逐字照抄**，大小写错误会导致调用失败。

---

## 第二步：复制下面的骨架

把下面两条分隔线之间的内容复制进新的 `SKILL.md`，替换 `{{...}}` 占位符。

## 写 SQL 类技能的补充片段

如果技能里要写 SQL（就像 `sqlserver-readonly-query` 那样），在"参数与写法约定"一节补上这些：

**只读边界**——把服务端会拦截的关键字明确写出来，让 AI 一次就写对：

```
只允许单条 SELECT / WITH。以下会被拒绝：
INSERT / UPDATE / DELETE / MERGE / TRUNCATE / CREATE / ALTER / DROP /
EXEC / EXECUTE / SELECT ... INTO / OPENROWSET / OPENQUERY / 分号多语句。
```

**方言提醒**——不同数据库语法差异是最常见的失败来源：

| 数据库 | 取前 N 行 | 拼接 | 当前时间 | 标识符引用 |
| --- | --- | --- | --- | --- |
| SQL Server | `SELECT TOP n` | `+` | `GETDATE()` | `[name]` |
| MySQL | `LIMIT n` | `CONCAT()` | `NOW()` | `` `name` `` |
| PostgreSQL | `LIMIT n` | `||` | `NOW()` | `"name"` |
| Oracle | `FETCH FIRST n ROWS ONLY` | `||` | `SYSDATE` | `"NAME"` |

**常用探查语句**（放进工作流第一步）：

```sql
-- 表清单
SELECT TABLE_SCHEMA, TABLE_NAME FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_TYPE='BASE TABLE';
-- 字段定义
SELECT COLUMN_NAME, DATA_TYPE, IS_NULLABLE FROM INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME='{{表名}}';
-- 数据规模（先探规模再拉明细）
SELECT COUNT(*) FROM {{表名}};
```

**结果控制**——务必写清默认行数上限与上调方式，否则 AI 容易拉全表把上下文撑爆。

## 上线前检查清单

- [ ] `name` 是 kebab-case，与目录名一致
- [ ] `description` 里包含用户**可能真实说出的口语触发词**
- [ ] 工具名逐字核对过，没有拼写/大小写错误
- [ ] 工作流是"先探查、后操作"，无副作用的步骤排在前面
- [ ] 明确写出了**不能做什么**（安全边界）
- [ ] 常见错误表至少覆盖 3 类实际会遇到的失败
- [ ] 结果呈现要求"先结论后细节"
- [ ] 拿一个真实问题完整跑一遍，确认流程可走通

## 放置位置

| 作用域 | 路径 | 适用 |
| --- | --- | --- |
| 用户级 | `~/.workbuddy/skills/<name>/SKILL.md` | 所有项目通用（推荐） |
| 项目级 | `<工作区>/.workbuddy/skills/<name>/SKILL.md` | 只在本项目生效，可随代码提交共享 |

技能生效需要客户端重新加载技能目录；修改后若无反应，重启客户端或会话。
