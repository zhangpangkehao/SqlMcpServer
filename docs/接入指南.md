# SqlMcpServer 接入指南

让 AI 助手直接查询你的 SQL Server 数据库。**本服务器只读**——AI 能查数据、看结构、做统计，但无法修改任何内容。

---

## 一、交付内容

| 文件 / 目录 | 说明 |
| --- | --- |
| `dist/win-x64-selfcontained/SqlMcpServer.exe` | **推荐**。自包含单文件，不需要安装 .NET 运行时，复制到哪都能跑 |
| `dist/win-x64-framework/SqlMcpServer.exe` | 体积小，但目标机器需已安装 .NET 9 运行时 |
| `src/SqlMcpServer/` | 完整源码（C# / .NET 9） |
| `skills/sqlserver-readonly-query/` | 让 AI 懂得如何查库的技能包 |
| `skills/mcp-skill-template/` | 新增其它 MCP 技能用的样板 |
| `build/dnet.sh` | 构建脚本（仅限类 Unix 沙箱环境使用，见附录二） |

## 二、快速开始（三步）

### 第 1 步：放置程序

把 `SqlMcpServer.exe` 复制到一个**固定且不会被清理**的目录，例如：

```
D:\tools\SqlMcpServer\SqlMcpServer.exe
```

> 建议单独建一个文件夹。程序会在同目录读写 `appsettings.json`。

### 第 2 步：配置数据库连接

**双击 `SqlMcpServer.exe`**，进入交互式控制台：

```
  [1] 测试数据库连接
  [2] 配置数据库连接（写入 appsettings.json）
  [3] 执行只读查询（交互式自测）
  [4] 生成 MCP 客户端配置片段
  [5] 查看可用工具
  [0] 退出
```

依次操作：

1. 选 **`2`**，按提示填写服务器地址、端口、数据库、账号密码，回车保存。
2. 选 **`1`**，确认显示 `[成功] 连接成功：…`。
3. 选 **`3`**，随便跑一条 `SELECT 1`，确认能返回结果。

如果第 1 步失败，先跳到本文第六节排查。

> **更稳妥的做法**：不要用 `sa`。请让 DBA 新建一个只读账号：
> ```sql
> CREATE LOGIN mcp_reader WITH PASSWORD = '强密码';
> USE [你的数据库];
> CREATE USER mcp_reader FOR LOGIN mcp_reader;
> ALTER ROLE db_datareader ADD MEMBER mcp_reader;
> ```
> 这样即使程序出问题，数据库层面也改不了数据——形成第二道防线。

### 第 3 步：挂载到 AI 客户端

在控制台里选 **`4`**，程序会生成一段可直接粘贴的 JSON，形如：

```json
{
  "mcpServers": {
    "sqlserver": {
      "command": "D:\\tools\\SqlMcpServer\\SqlMcpServer.exe",
      "args": [],
      "env": {
        "MSSQL_SERVER": "localhost",
        "MSSQL_DATABASE": "你的数据库",
        "MSSQL_USER": "mcp_reader",
        "MSSQL_PASSWORD": "你的密码",
        "MSSQL_TRUST_SERVER_CERTIFICATE": "true"
      }
    }
  }
}
```

把 `mcpServers` 里的 `sqlserver` 这一项合并进对应客户端的配置文件即可，具体位置见第四节。

## 三、配置方式详解

配置优先级：**命令行参数 > 环境变量 > `appsettings.json` > 内置默认值**。

### 3.1 配置文件 `appsettings.json`

由控制台向导自动生成，放在 exe 同目录：

```json
{
  "mssql": {
    "server": "localhost",
    "port": 1433,
    "database": "YourDatabase",
    "user": "mcp_reader",
    "password": "your-password",
    "integratedSecurity": false,
    "encrypt": true,
    "trustServerCertificate": true,
    "maxRows": 200,
    "commandTimeoutSeconds": 30,
    "connectTimeoutSeconds": 15
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `server` | 主机名、IP，或命名实例 `主机名\实例名` |
| `port` | 端口，默认实例通常 1433；留 `null` 表示不显式指定 |
| `database` | 默认连接的数据库 |
| `user` / `password` | SQL 登录账号；用集成认证时留空 |
| `integratedSecurity` | `true` 使用 Windows 当前用户身份登录，免密码 |
| `encrypt` | 是否加密传输。SQL Server 2022 起默认 `true` |
| `trustServerCertificate` | 使用自签名证书时设为 `true`，否则握手会失败 |
| `maxRows` | 单次查询最多返回给 AI 的行数，默认 200 |
| `commandTimeoutSeconds` | 查询超时（秒） |

> **关于密码明文**：`appsettings.json` 中的密码是明文。请收紧该文件的访问权限（右键 → 属性 → 安全，仅保留当前用户），不要放进 Git 仓库，也不要放在多人共用的目录。

### 3.2 环境变量

适合把凭据放在 MCP 客户端的 `env` 块里，避免落地到文件：

| 变量 | 对应配置 |
| --- | --- |
| `MSSQL_SERVER` | `server` |
| `MSSQL_PORT` | `port` |
| `MSSQL_DATABASE` | `database` |
| `MSSQL_USER` | `user` |
| `MSSQL_PASSWORD` | `password` |
| `MSSQL_INTEGRATED_SECURITY` | `integratedSecurity`（`true`/`false`） |
| `MSSQL_ENCRYPT` | `encrypt` |
| `MSSQL_TRUST_SERVER_CERTIFICATE` | `trustServerCertificate` |
| `MSSQL_MAX_ROWS` | `maxRows` |
| `MSSQL_COMMAND_TIMEOUT` | `commandTimeoutSeconds` |
| `MSSQL_CONNECT_TIMEOUT` | `connectTimeoutSeconds` |
| `MSSQL_CONNECTION_STRING` | 直接给完整连接串（高级用法） |
| `MSSQL_DEBUG=1` | 在 stderr 输出诊断日志 |

### 3.3 命令行参数

用于快速自测：

```bat
SqlMcpServer.exe --test
SqlMcpServer.exe --server localhost --integrated --test
SqlMcpServer.exe --server "192.168.1.10,1433" --user sa --password *** --database master --test
SqlMcpServer.exe --init
SqlMcpServer.exe --help
```

## 四、各客户端接入方法

MCP 的 `mcpServers` 配置格式在各客户端间基本一致，只是**文件位置**不同。

### 4.1 WorkBuddy / CodeBuddy

配置文件：`C:\Users\<用户名>\.workbuddy\mcp.json`

```json
{
  "mcpServers": {
    "sqlserver": {
      "command": "D:\\tools\\SqlMcpServer\\SqlMcpServer.exe",
      "args": [],
      "env": {
        "MSSQL_SERVER": "localhost",
        "MSSQL_DATABASE": "YourDatabase",
        "MSSQL_INTEGRATED_SECURITY": "true",
        "MSSQL_TRUST_SERVER_CERTIFICATE": "true"
      }
    }
  }
}
```

> **注意**：新增的自定义 MCP **不会自动生效**。保存后需要到「连接器管理」页面，点击右上角的自定义连接器入口，找到 `sqlserver` 并点击「信任」，之后才能使用。

### 4.2 Claude Desktop

配置文件：`%APPDATA%\Claude\claude_desktop_config.json`

即使客户端是中文界面，配置键名仍然用 `mcpServers`。改完**完全退出并重启** Claude Desktop 才会加载。

```json
{
  "mcpServers": {
    "sqlserver": {
      "command": "D:\\tools\\SqlMcpServer\\SqlMcpServer.exe",
      "args": [],
      "env": {
        "MSSQL_SERVER": "localhost",
        "MSSQL_DATABASE": "YourDatabase",
        "MSSQL_INTEGRATED_SECURITY": "true",
        "MSSQL_TRUST_SERVER_CERTIFICATE": "true"
      }
    }
  }
}
```

### 4.3 Cursor

配置文件：`C:\Users\<用户名>\.cursor\mcp.json`（全局），或在项目下建 `.cursor\mcp.json`（项目级）。

### 4.4 VS Code（Copilot Chat）

项目级配置文件：`<项目>\.vscode\mcp.json`

```json
{
  "servers": {
    "sqlserver": {
      "type": "stdio",
      "command": "D:\\tools\\SqlMcpServer\\SqlMcpServer.exe",
      "args": [],
      "env": {
        "MSSQL_SERVER": "localhost",
        "MSSQL_DATABASE": "YourDatabase",
        "MSSQL_INTEGRATED_SECURITY": "true"
      }
    }
  }
}
```

> VS Code 用的是 `servers` 键而非 `mcpServers`，且需要 `"type": "stdio"`。

### 4.5 其它支持 MCP 的客户端

凡支持 stdio 类型 MCP 的客户端，填写方式都一样：

- **命令 / Command**：`SqlMcpServer.exe` 的绝对路径
- **参数 / Args**：留空
- **环境变量 / Env**：填入 `MSSQL_*`

**路径务必用绝对路径**，并且 JSON 里的反斜杠要写成双反斜杠 `\\`。

## 五、安全性：只读是怎么保证的

不是靠"提醒 AI 不要乱来"，而是**在程序内核里强制拦截**。每次调用会经过这些检查：

1. **词法预处理** —— 把字符串字面量、方括号标识符、`--` 与 `/* */` 注释全部中性化，只在剩余的代码骨架里做判断。这样写操作关键字既不能用引号藏起来，也不能用注释拼出来。
2. **单语句约束** —— 出现分号拼接的语句直接拒绝，`SELECT 1; DROP TABLE x` 这类无法通过。
3. **开头约束** —— 必须以 `SELECT` 或 `WITH` 开头。
4. **关键字黑名单** —— 命中即拒绝：

   `INSERT` `UPDATE` `DELETE` `MERGE` `TRUNCATE` `CREATE` `ALTER` `DROP` `GRANT` `REVOKE` `DENY` `EXEC` `EXECUTE` `BACKUP` `RESTORE` `SHUTDOWN` `DBCC` `BULK` `OPENROWSET` `OPENQUERY` `OPENDATASOURCE` `WAITFOR` `INTO` …

5. **行数与超时上限** —— 单次最多返回 `maxRows` 行（默认 200），查询超时默认 30 秒，单元格超长内容自动截断。

被拒绝时返回 `isError: true`，并明确告诉 AI 是哪个关键字违规。

**两道防线建议**：程序侧拦截 + 数据库侧只读账号（`db_datareader`）。只读账号能挡住程序升级换代时可能出现的疏漏。

## 六、常见问题排查

| 现象 | 原因与处置 |
| --- | --- |
| `无法与 SQL Server 建立会话` / 错误码 233、10061 | 实例未启动，或未启用 TCP/IP。打开「SQL Server 配置管理器」→ SQL Server 网络配置 → 协议 → 启用 TCP/IP，重启服务；确认防火墙放行 1433 |
| `找不到服务器或实例` / 错误码 53、40 | 服务器地址写错。命名实例要写成 `主机名\实例名`，并确认 SQL Server Browser 服务在运行 |
| `登录失败` / 错误码 18456 | 账号密码错，或实例只允许 Windows 认证。在 SSMS 里把服务器属性 → 安全性 → 改为「SQL Server 和 Windows 身份验证模式」，然后重启服务 |
| `该登录名来自不受信任的域，不能与集成身份验证一起使用` | 用了 `127.0.0.1` 这类 IP 走集成认证。改用 `localhost` 或 `.`，或者改用 SQL 登录账号 |
| `权限不足` / 错误码 229、230 | 账号没有该表的 SELECT 权限。授予 `db_datareader` 角色 |
| `对象不存在` / 错误码 208 | 库名、架构名或表名不对。让 AI 先调 `list_tables`、`describe_table` |
| 证书 / SSL 握手报错 | 保持 `trustServerCertificate: true`；或为 SQL Server 配置受信任证书 |
| 客户端里看不到 `sqlserver` 工具 | ① 配置后未重启客户端；② 未在连接器管理页点「信任」；③ exe 路径不是绝对路径或含中文空格未正确转义 |
| AI 说"工具调用失败"但没有细节 | 在 `env` 里加 `"MSSQL_DEBUG": "1"`，程序会把诊断信息输出到 stderr，可在客户端日志里查看 |

**手工验证 MCP 是否工作**（不依赖任何客户端）：

```bat
echo {"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"t","version":"1"}}} | SqlMcpServer.exe --stdio
```

能返回一段带 `serverInfo` 的 JSON，说明服务本身正常，问题在客户端配置。

## 七、提供的工具清单

| 工具 | 用途 |
| --- | --- |
| `execute_readonly_query` | 执行单条只读查询。参数：`sql`（必填）、`maxRows`、`format`（`markdown`/`json`/`csv`） |
| `list_databases` | 列出实例上的全部数据库及状态 |
| `list_tables` | 列出指定库的用户表，可按架构过滤 |
| `describe_table` | 查看表的字段定义（列名、类型、长度、可空、默认值） |
| `get_server_info` | 确认连接目标、版本与登录账号 |

典型用法（直接对 AI 说）：

> - "看看这个库里有几张表"
> - "订单表里 9 月份的记录有多少条？"
> - "把上个月的销售按地区汇总一下"
> - "帮我写一条 SQL，找出状态为异常的订单"

## 附录一：让 AI 更懂你的库（技能包）

把 `skills/sqlserver-readonly-query/` 整个目录复制到：

```
C:\Users\<用户名>\.workbuddy\skills\sqlserver-readonly-query\
```

（项目专属的话，放到 `<工作区>\.workbuddy\skills\` 下。）

它会告诉 AI：先探查结构再查询、用 T-SQL 方言、结果按"先结论后表格"呈现、遇到拒绝如何改写。

要新增别的 MCP 技能，以 `skills/mcp-skill-template/SKILL.md` 为样板复制修改即可。

## 附录二：从源码自行构建

普通 Windows 终端（PowerShell / CMD）：

```bat
cd src\SqlMcpServer
dotnet restore
dotnet publish -c Release -r win-x64 --self-contained true ^
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true ^
  -o ..\..\dist\win-x64-selfcontained
```

需要 .NET 9 SDK。`IncludeNativeLibrariesForSelfExtract` 必须加，否则 SQL Server 的原生 SNI 组件不会被打进单文件。

> `build/dnet.sh` 是给受限沙箱环境用的辅助脚本：某些自动化 shell 不暴露 `PROGRAMFILES`/`APPDATA` 等变量，会让 NuGet 报 `The type initializer for 'NuGet.Configuration.ConfigurationDefaults' threw an exception`。脚本重新注入这些变量后再调用 `dotnet`。在正常 Windows 终端下**不需要**它。
